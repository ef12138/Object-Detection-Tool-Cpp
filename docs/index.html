Object Detection Tool 2.2

纯 C++ / Qt 写的三角州行动实时目标检测自动瞄准工具

抓屏幕中心的一块画面 → 跑目标检测 → 把框画回屏幕上 → 按住某个键时，把鼠标朝目标方向推一点。

市面上很多这类小工具，是把现成的 Python 脚本、现成的库拼起来。抓屏走 DXGI Desktop Duplication，推理走 ONNX Runtime（DirectML 后端），绘制部分是一个透明置顶的 Qt 窗口。参数全部落在 exe 同目录的 config.ini 里。本机实测：256 档约 276 fps，640 档约 202 fps。

一、界面与功能

1.1 主界面：检测页

左边是 7 个导航项（检测 / 推理 / PID / 贝塞尔曲线 / 瞄准位置 / 快捷键 / 关于），右边是当前页。

检测页只放三样东西：模型输入尺寸（256 / 320 / 416 / 640）、开始检测、绘制。

尺寸这一档值得单独解释：抓屏区域是固定的 640×640，尺寸选的是"这块画面送进模型前缩到多大"，所以四档真正的差别就体现在每帧推理要花多少毫秒上。

1.2 六个功能页

页面截图：

几个设计细节：

  • 参数改完立即落盘，不需要点保存。滑块拖动、数值框提交都会写 config.ini 并 sync()——Qt 默认只在 QSettings 析构时写盘，进程被强杀就丢了，这里改成即时同步。

1.3 深浅两套主题

默认跟随系统（读注册表 AppsUseLightTheme，并监听 WM_SETTINGCHANGE 实时切换），也可以在 config.ini 里写死 theme=light / theme=dark。

深色不是简单地把白底反色——外壳（标题栏 + 侧栏）用 #1f1f1f、内容页 #141414、卡片 #2c2c2c，层次比纯黑舒服。系统标题栏也不是自绘的假标题栏，是用 DWM 的 DWMWA_CAPTION_COLOR 染的真标题栏，所以最小化 / 最大化 / 关闭按钮、拖拽、贴边分屏全都是系统原生行为。

二、核心代码

先看整体：

三条线：UI 只负责收发参数和启停；推理循环做"抓屏 → 预处理 → 推理 → 后处理"；控制层拿推理结果算出鼠标该走多少；叠加层是另一条 144Hz 的独立循环，只画不算。

真正决定这个工具能不能用的，就是后面两条线。下面按数据流顺序，推理循环拆五段、控制层拆四段。

2.1 推理循环（五段）

1抓屏：DXGI Desktop Duplication

dxgi/dxgi.cpp。选它而不是 BitBlt：BitBlt 要过一遍 GDI 拷贝，1080p 一帧就是几毫秒，还会和窗口重绘打架；Desktop Duplication 直接拿 D3D11 纹理，只在我们需要的区域做一次 CopySubresourceRegion。

C++
// 不阻塞：有帧就拿，没帧立刻返回
HRESULT hr = dup->AcquireNextFrame(0, &frameInfo, &desktopResource);
if (hr == DXGI_ERROR_WAIT_TIMEOUT) return QImage();   // 桌面没变化

// 只把屏幕中心那一块拷到 STAGING 纹理（CPU 可读）
D3D11_BOX box = { left, top, 0, right, bottom, 1 };
ctx->CopySubresourceRegion(texCopy, 0, 0, 0, 0, tex, 0, &box);

// 映射到 CPU 内存，逐像素把 BGRA 换成 RGBA
ctx->Map(texCopy, 0, D3D11_MAP_READ, 0, &mapped);
for (int y = 0; y < h; ++y) {
    uchar* src = (uchar*)mapped.pData + y * mapped.RowPitch;
    uchar* dst = image.scanLine(y);
    for (int x = 0; x < w; ++x) {
        dst[x*4+0] = src[x*4+2];   // R
        dst[x*4+1] = src[x*4+1];   // G
        dst[x*4+2] = src[x*4+0];   // B
        dst[x*4+3] = src[x*4+3];   // A
    }
}

三个容易踩的点：

  1. 超时是正常的。AcquireNextFrame(0) 在桌面静止时返回 DXGI_ERROR_WAIT_TIMEOUT，这不是错误，直接返回空图、等下一轮就行。用 INFINITE 反而会把整个界面卡死。
  2. 每帧都要 ReleaseFrame()。取到帧不释放，下一帧就 Acquire 不到，程序会"跑着跑着就不动了"。
  3. DPI 换算。抓回来的是物理像素，配置里写的是逻辑像素。125% 缩放下如果不换算，你要 640 会拿到 512：
C++
qreal physicalToLogicalScaleX = (qreal)logicalGeometry.width() / desc.Width;
int physicalCaptureWidth  = m_captureWidth  / physicalToLogicalScaleX;
int physicalCaptureHeight = m_captureHeight / physicalToLogicalScaleY;

为什么非要拿 D3D11 纹理，而不是直接截屏？

这是整套工具能自洽的前提，值得单独讲——因为屏幕上已经有我们自己画的东西了：检测框、目标点、性能文本，全在一个透明置顶的叠加窗口里。任何"把屏幕截下来"的方案都会把这些框一起抓回去当下一帧的输入，于是形成自反馈：

  • 框被当成画面内容喂给模型，模型在框上再出框；
  • 每帧叠一层，两秒钟框就"实"成一块色块；
  • 输入被输出污染，检测结果从此不可信，而且程序不会报任何错。

所以这里有两道保险，缺一不可。

第一道：让叠加层对抓屏不可见。 draw/draw.cpp 里，叠加窗口一建出来就声明"我不参与截屏"：

C++
setAttribute(Qt::WA_TranslucentBackground);
setAttribute(Qt::WA_TransparentForMouseEvents);   // 鼠标穿透，不挡下面的点击
setWindowFlags(Qt::FramelessWindowHint | Qt::Tool | Qt::WindowStaysOnTopHint);

HWND hwnd = (HWND)winId();
SetWindowLong(hwnd, GWL_EXSTYLE,
              GetWindowLong(hwnd, GWL_EXSTYLE) | WS_EX_LAYERED | WS_EX_TRANSPARENT);
SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE);   // 关键这一行

WDA_EXCLUDEFROMCAPTURE 之后，这个窗口在系统合成输出里就是"空"的：人眼看得见框，抓屏拿到的是它下面干净的桌面。绘图和采集从此互不干扰——这才是叠加层存在的意义，否则画得越准，错得越狠。

第二道：纹理只拷我们那 640×640。 Desktop Duplication 交出来的是整屏纹理，不把它整块搬进内存再裁，而是在 GPU 上做一次 CopySubresourceRegion 只框出中间那块，之后才 Map 到 CPU 取像素。对比 BitBlt：1080p 每帧要过一遍 6~8 MB 的 GDI 拷贝，还得和窗口重绘抢 GDI 锁；现在是显存里拷一小块，实测抓屏耗时不到 1 ms，且完全不碰 GDI，也就不会因为我们自己在全屏上重绘而掉帧。

2预处理：letterbox，不是硬拉伸

onnxruntime/onnxruntime.cpp。YOLO 系列训练时用的是 letterbox（等比缩放 + 灰边填充），推理时必须保持一致，否则宽高比一变形，框就会偏。

C++
float ratio = std::min((float)inH / img.height(), (float)inW / img.width());
int new_w = img.width() * ratio, new_h = img.height() * ratio;

QImage canvas(inW, inH, QImage::Format_RGB888);
canvas.fill(QColor(114, 114, 114));          // letterbox 的灰
pasteX = (inW - new_w) / 2;
pasteY = (inH - new_h) / 2;
painter.drawImage(pasteX, pasteY, resized);

114 这个灰度不是随便取的，是训练时的填充值（114/255），换成 0 或 255 会让边缘区域的预测漂一点。

ratio / pasteX / pasteY 三个数必须一路带到后处理，因为模型输出的坐标是"画布坐标"，最后要减掉边、再除回去才是原图坐标。

张量按 CHW + 归一化铺：

C++
for (int c = 0; c < 3; ++c)
    for (int y = 0; y < inH; ++y)
        for (int x = 0; x < inW; ++x)
            tensor.push_back(image.constScanLine(y)[x * 3 + c] / 255.0f);

3推理：DirectML 优先，失败自动回退

C++
Ort::SessionOptions opt;
opt.SetIntraOpNumThreads(1);
opt.SetGraphOptimizationLevel(GraphOptimizationLevel::ORT_ENABLE_ALL);

if (useGPU) {
    try {
        std::unordered_map<std::string, std::string> dml = {
            {"device_id", std::to_string(gpuDeviceId)}     // 从 config.ini 读
        };
        opt.AppendExecutionProvider("DML", dml);
    } catch (const Ort::Exception& e) {
        // 没有 DML DLL、显卡不支持 —— 记一条日志，继续用 CPU 跑
    }
}
m_session = Ort::Session(env, wideModelPath.c_str(), opt);

SetIntraOpNumThreads(1) 是刻意的：这是每帧都要跑的小图推理，多线程的调度开销比并行收益更大，还会和抓屏线程抢核。

输入输出尺寸不写死，从 session 里读回来：

C++
auto inShape = session.GetInputTypeInfo(0).GetTensorTypeAndShapeInfo().GetShape();
m_inputH = inShape[2]; m_inputW = inShape[3];          // [1, 3, H, W]

auto outShape = session.GetOutputTypeInfo(0).GetTensorTypeAndShapeInfo().GetShape();
m_numBoxes   = outShape[2];                             // [1, 4+classes, boxes]
m_numClasses = outShape[1] - 4;

这样换一个 320 的模型、或者类别数不同的模型，都不用改代码——上面四档尺寸之所以能一键切换，靠的就是这里。

4后处理：sigmoid + 阈值 + 同类别 NMS

输出是通道优先的 [1, 4+C, N]，不是常见的 [1, N, 4+C]。取第 i 个框的第 c 个类别分数要写成：

C++
float score = output[(4 + c) * num_detections + i];

把它当成 output[i * (4+C) + c] 读，会得到一堆随机框——这是换模型时最常见的一处静默错误：程序不崩，只是结果全错。

置信度是 logits，要过 sigmoid：

C++
auto sigmoid = [](float x) { return 1.0f / (1.0f + std::exp(-x)); };
float conf = sigmoid(output[(4 + maxClass) * num_detections + i]);
if (conf < m_confidenceThreshold) continue;

坐标反算回原图（前面埋的 ratio / paste 在这里用上）：

C++
int left   = (cx - 0.5f * w - pasteX) / ratio;
int top    = (cy - 0.5f * h - pasteY) / ratio;
int width  = w / ratio;
int height = h / ratio;

NMS 只抑制同类别的重叠框：

C++
std::sort(order.begin(), order.end(),
          [&](int i, int j) { return confidences[i] > confidences[j]; });

for (size_t i = 0; i < order.size(); ++i) {
    if (suppressed[order[i]]) continue;
    kept.push_back(order[i]);
    for (size_t j = i + 1; j < order.size(); ++j) {
        if (classIds[order[i]] != classIds[order[j]]) continue;   // 跨类别不抑制
        float iou = /* 交集 / (面积和 - 交集) */;
        if (iou > m_nmsThreshold) suppressed[order[j]] = true;
    }
}

跨类别不抑制很关键：两个不同类别的目标贴在一起时，如果跨类别也做 NMS，会把本来正确的两个框压成一个。

5调度：两个定时器，一条串行链

C++
void ScreenCaptureWidget::startCapture() {
    if (m_inferenceTimer->isActive()) {
        m_inferenceTimer->stop();
        m_drawTimer->stop();
        m_drawWindow->clearDrawInfo();          // 停止时把残留框清掉
    } else {
        m_inferenceTimer->start(m_frequency);   // 推理频率（0 = 不留间隔）
        m_drawTimer->start(1000 / 144);         // 叠加层固定 144Hz
    }
}

void ScreenCaptureWidget::captureFrame() {
    m_inferenceTimer->stop();                   // 关键：先停，做完再 start
    QImage img = m_dxgi->captureCenterScreen();
    auto dets  = m_onnxRuntime->inference(img);
    // …更新叠加层数据、更新目标列表、驱动鼠标
    m_inferenceTimer->start(m_frequency);
}

stop() → 做事 → start() 解决两个问题：

  • 不会重入。QTimer 由事件循环驱动，单次推理如果超过设定间隔，下一次 timeout 已经在队列里等着，两帧叠在一起抢同一个 session，轻则掉帧重则崩。先停再启就变成天然的串行链。
  • 频率是"做完之后再等"，不是固定节拍。设 0 表示不等，跑满为止。

2.2 控制层（四段）

1闸门：按住才动，松手即停

mouse/mouse_controller.cpp。整段逻辑被一个"是否按住"卡住：

C++
bool hotkey1Pressed = (GetAsyncKeyState(m_hotkey1) & 0x8000);
bool hotkey2Pressed = (GetAsyncKeyState(m_hotkey2) & 0x8000);
if (!(hotkey1Pressed || hotkey2Pressed)) return;      // 松手立即停

热键用 GetAsyncKeyState 轮询，而不是 RegisterHotKey 或键盘钩子：RegisterHotKey 只给一次按下事件，没有"按住"这个语义。

2误差：目标锚点到屏幕中心

误差的定义要看清楚：是目标锚点到屏幕中心的距离，不是到准星的距离（两者通常重合，但代码里写的是屏幕中心）。

C++
int tx = target.x + target.width  * m_targetOffsetX;
int ty = target.y + target.height * (1.0 - m_targetOffsetY);   // Y 反一下
double dx = tx - screenCenterX, dy = ty - screenCenterY;

(1.0 - offsetY) 是给"命中点在框内的相对高度"用的：UI 上 Y 越大越靠上，而屏幕坐标 Y 向下，所以要反。

3PID：把像素差换算成每帧位移

每轴一个控制器，输出再取反：

C++
double ctrlX = pidX_.compute(dx, dt);
int moveX = -static_cast<int>(ctrlX);    // setpoint 是 0，取反后才是"朝目标走"

PID 本体只有十几行：

C++
double error = setpoint_ - inputValue;               // setpoint_ = 0
double p = kp_ * error;
integral_ += error * deltaTime;
double i = ki_ * integral_;
double d = kd_ * (error - prevError_) / deltaTime;   // 注意这里除了 dt
return std::clamp(p + i + d, minOutput_, maxOutput_);

有一个数值上的坑值得单独说：D 项除以了 deltaTime。按 16ms 一帧算，等于把误差变化放大 62.5 倍。所以 Kd = 0.042 的实际增益是 2.6，而 Kp = 0.63 只有 0.63——D 才是三项里最猛的，不是 P。很多人在这里调大 Kd 想"加阻尼"，结果直接开始抖。

deltaTime 取自 GetTickCount()，暂停、卡帧、拖窗口都会让它异常（甚至为 0 导致除零），所以有兜底：

C++
if (deltaTime <= 0.0 || deltaTime > 1.0) deltaTime = 0.016;

4贝塞尔：把一次位移拆成多段走

C++
p1 = rand01() * randomFactor;                 // 控制点 1 沿"起点→终点"方向的比例
p2 = 1.0 - rand01() * randomFactor;           // 控制点 2
double p1x = dx * p1, p1y = dy * p1;
double p2x = dx * p2, p2y = dy * p2;

for (int i = 0; i <= steps; ++i) {
    double t = (double)i / steps;
    auto pt = cubicBezier(t, 0,0, p1x,p1y, p2x,p2y, dx,dy);
    int mx = (int)pt.first - prevX, my = (int)pt.second - prevY;
    if (mx || my) win32::moveMouseRelative(mx, my);   // SendInput 相对位移
    prevX = (int)pt.first; prevY = (int)pt.second;
    if (stepDelay) Sleep(stepDelay);                   // stepDelay = 总耗时 / steps
}

控制点不是随机飞到四面八方，而是沿着位移方向取两个比例值，所以曲线永远从起点走向终点，只是中间的节奏不同。randomFactor = 0 时退化成直线。

速度 这个参数叫速度，实际含义是这一整段位移的总耗时（毫秒），会平摊到每一步：

C++
int stepDelayMs = (steps > 0 && m_moveDelayMs > 0) ? m_moveDelayMs / steps : 0;

所以调大"速度"鼠标反而变慢——这个反直觉的点在关于页里写明了。
